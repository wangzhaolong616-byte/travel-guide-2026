# 📖 04 · 项目结构与源码说明

面向想读懂、修改、二次开发本项目的人。整个项目 = **内容数据（JSON）+ 页面模板（HTML/CSS/JS）+ 构建脚本（Python）**，产物是**一个零依赖的单文件 HTML**。

---

## 1. 设计理念：为什么是单文件？

- **零依赖**：无 CDN、无框架、无字体请求，断网/内网/老旧电脑都能打开
- **可分发**：一个文件发微信、进云盘、拷 U 盘即完成"部署"
- **可托管**：放进 GitHub Pages 仓库根目录就是网站

## 2. 目录结构与文件职责

```
travel-guide-2026/
├── index.html              ← 🌐 在线版入口（= 离线版的拷贝，Pages 托管此文件）
├── 中国旅行宝典2026.html    ← 💾 离线版（构建产物）
├── README.md               ← 项目总览
├── docs/                   ← 本目录：四份学习文档
├── content/                ← 📦 数据层：34 个省级行政区 JSON（一个省一个文件）
├── template.html           ← 【模板层】全部 CSS/HTML 骨架/JS 逻辑
├── build.py                ← 【构建层】数据 + 模板 → 单文件 HTML
├── SPEC.md                 ← 内容生产规范（写新内容前必读）
├── tools/
│   ├── check_json.py       ← Schema 校验
│   └── lint_content.py     ← 脏数据体检
├── LICENSE                 ← MIT
└── .gitignore
```

| 文件 | 职责 | 会手改吗 |
|---|---|---|
| `content/*.json` | 全部攻略内容 | ✅ 主要改这里 |
| `template.html` | 界面与交互逻辑 | ✅ 加功能时改 |
| `build.py` | 构建管线 | 偶尔（改输出/统计） |
| `SPEC.md` | 内容写作规范 | 补充规范时 |
| `index.html` / `中国旅行宝典2026.html` | **构建产物，不要手改**（会被下次构建覆盖） | ❌ |

## 3. 构建管线

```
content/*.json (34个) ──┐
                        ├──►  build.py  ──►  中国旅行宝典2026.html + index.html
template.html ──────────┘
```

`build.py` 做四件事：读取并排序 34 个 JSON（按地理区 → 预设顺序 → 评级）→ 统计数据规模 → 把内容数组以 `const DATA=[...]`、月历以 `const CALENDAR=[...]` 注入模板的 `__DATA__` / `__CALENDAR__` 占位符 → 输出两个 HTML（并自动复制一份到桌面）。

运行：`python build.py`（需要 Python 3.10+，无第三方依赖）。

## 4. 数据 Schema（content/*.json）

顶层字段（完整规范与示例见根目录 [SPEC.md](../SPEC.md)）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` / `region` / `emoji` / `grade` | str | 省名 / 八大地理区枚举 / 图标 / 评级（顶流必去·黑马新贵·小众宝藏） |
| `tagline` / `summary` | str | 一句话卖点 / 120-180 字简介 |
| `tags` | str[] | 主题标签（筛选器数据源） |
| `bestSeason` / `suggestedDays` / `budget` | str | 最佳季节 / 建议天数 / 预算 |
| `cities` | obj[] | 城市数组（见下） |
| `signatureFood` | {name,desc}[] | 省级美食榜 |
| `topSights` | {name,type,desc}[] | 景点榜，type ∈ 世界遗产/5A景区/自然奇观/人文古迹/小众秘境/主题乐园 |
| `experiences` | {name,desc}[] | 演出/夜生活/节庆/非遗/户外等体验 |
| `souvenirs` | str[] | 伴手礼（`名称（一句话）`） |
| `routes` | {title,days[]}[] | 路线推荐（经典 + 深度/主题线） |
| `transport` | str | 交通与预算 |
| `pitfalls` | str[] | 避坑清单 |
| `fresh` | str[] | 2023-2026 新动态 |
| `py` | str | 拼音（构建时自动从文件名注入，用于拼音搜索） |

**cities 元素**：`{name, tagline, intro, districts:[{name,note}], sights:[], food:[], foodStreets:[], stay}`。直辖市规则：每个"城市"= 一个市辖区，`districts` 写区内板块；普通城市的 `districts` 可含重点县。

## 5. 模板（template.html）关键结构

- **CSS**：`:root` 设计变量（`--bg/--card/--ink/--accent` 等，深色模式即换变量）；`.r0-.r7` 八大区主题色渐变；`[hidden]{display:none!important}` 保证显隐可靠
- **数据注入点**：脚本开头的 `const DATA=__DATA__;` 与 `const CALENDAR=__CALENDAR__;`
- **路由**：hash 路由。`#/` 首页，`#/p/省名` 详情页；`hashchange → route()` 分发到 `openDetail()` / 首页渲染
- **渲染函数**：`renderGrid()`（卡片墙）、`detailHTML()`（详情页拼装）、`renderMonths()`（月历）、`renderMapModal()`（足迹地图）
- **状态**：`state`（筛选/排序/搜索词）、`homeScroll`（返回滚动位置）、`curDetail`（当前省份，供键盘翻页）
- **本地存储键**：`ctw_wish`（想去清单）、`ctw_visited`（足迹）、`ctw_achv`（已解锁成就）、`ctw_pack_<省名>`（该省清单勾选）、`ctw_theme`（深浅色）

## 6. 实操：修改一个省的内容

1. 打开 `content/<省拼音>.json`，按 SPEC 修改（保持 JSON 合法：无注释、无尾逗号、中文引号）
2. `python tools/check_json.py` 校验
3. `python build.py` 重建
4. 浏览器打开本地 HTML 检查 → `git add . && git commit -m "说明" && git push`
5. Pages 约 1 分钟后自动更新

## 7. 实操：新增一个功能（以模板为骨架）

- **纯展示**：在 `detailSections()` 加一个 section，数据用 JSON 新字段，同步更新 SPEC 与 `tools/check_json.py`
- **新交互**：顶栏/详情页加按钮 → JS 加监听 → 需要持久化就新增一个 `ctw_*` 存储键（参考足迹地图的实现：数据数组 + toggle + localStorage + 重渲染）
- **新筛选维度**：往 `tags` 词库加词 → 主题筛选 chips 会自动收录（按出现频率取前 12）

## 8. 已知边界与注意事项

- 纯前端应用：数据在浏览器本地，无后端、无账号体系
- `index.html` 与离线版是构建产物，**不要手改**（会被下次 build 覆盖），改 `content/` 或 `template.html`
- 中文文件名在 GitHub Pages 上可直接访问，但分享链接时建议用根路径 `index.html`
- 若要迁移到 Vercel/Netlify：构建产物在仓库根目录，直接指向即可，无需改造
